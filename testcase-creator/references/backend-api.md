# Backend — Contract, Authorization, Input, and Errors (4/10 groups)

This reference is for understanding an E2E journey's API contract/security boundary or for linking a separate API suite; it is not a prompt to add a Backend section to an E2E file. Do not assume JWT, Redis, or HTTP 422. Obtain the OpenAPI/schema, role matrix, and BR/E/EC rules before setting expected results. For security discovery, consult the project-approved [OWASP Web Security Testing Guide](https://owasp.org/projects/web-security-testing-guide) only when in scope; use an authorized, isolated environment. A checklist subset is not proof of security.

## 1. API contract
Endpoint method/path; wrong method + `Allow`; unknown path (JSON, not framework HTML); slash/case conventions; missing/wrong Content-Type; status/body/schema, required fields/types, no internal or PII fields; response envelope, naming, null vs absent; datetime/timezone and numeric/currency representation; page/cursor boundaries 0/negative/max/out-of-range/zero total, metadata consistent with filters; invalid filter field/type/empty/combined filters; invalid/injection sort field and stable default tie-break; search `%`, `_`, wildcard/empty; CORS preflight if cross-origin; security headers; versioning/breaking change; UTF-8/emoji/full-width; payload near/over limit; repeat request determinism. Confirm environment base URL, contract, format, page and payload limits first.

## 2. Authentication & authorization
Missing auth, malformed/signature-invalid/expired token, locked/deleted user, logout/revocation, expired/reused refresh token; JWT `none`/algorithm confusion **only if JWT is used**; tenant A→B; insufficient role, another user's object in same tenant (IDOR), cross-tenant, admin-only/internal endpoint; mass assignment of `role`/`tenant_id`/`user_id`, forged identity headers, method override, path bypass/encoding/traversal, ID enumeration, login/OTP rate limiting, CSRF **if cookie auth is used**, login errors must not reveal account existence; service-to-service auth. Confirm `403` vs `404` enumeration policy, refresh TTL, gateway behavior, role × action × ownership × tenant matrix. Hiding a FE button does not replace these tests. Perform bypass probes only in an authorized environment.

## 3. Input validation
Absent/null/empty/all-whitespace; extra fields (mass assignment), duplicate JSON keys; empty/null/malformed JSON body, wrong media type; wrong types/coercion, invalid enum/case; negative/0/fraction/overflow/scientific/commas; string min/max/+1, trim, emoji/full-width; invalid dates/leap day/timezone; arrays 0/1/max/+1/wrong type/deep nesting; boolean as string/number; email/phone/address; conditional required fields; SQL/NoSQL injection, stored XSS on later reads, upload path traversal, command injection, SSRF URLs, LDAP/XML/XXE/template/header injection, CSV formula, log injection, unsafe deserialization; oversized payload, real MIME/zero-byte files, concurrent large payloads, deeply nested JSON. Confirm DTO/schema, allowlist, limits, normalization/escaping rules, and validation layer. Security scans require an isolated/approved environment; a few manual payloads cannot prove the absence of vulnerabilities.

## 4. Error handling & status
Consistent error envelope/code, field-level errors, correlation ID, JSON Content-Type, no `200 {error}`; distinguish 400/422 according to contract, 401/403/404/405+Allow/409/413/415/429+Retry-After; map DB unique/FK failures without leaking SQL; 500 must not disclose stack/SQL/path/library; DB/cache/third-party unavailable, timeout/degradation; API timeout; lost response after commit followed by retry; bulk partial success vs rollback; malformed JSON/encoding; file read/write failures; user-facing localized error owned by FE or BE. Confirm error register, timeouts, and failure policy. Negative tests verify **no side effects**, except where processing committed before the response was lost.

For a separate API suite, record auth, request, status/schema, side effects, trace, and source. In this E2E suite, use the contract only to ground the same user journey's oracle; unresolved status policy is not an E2E oracle and must not be guessed.
