# Gotchas & version drift

Read this before trusting a Refine snippet found outside this skill (older blog posts, Stack Overflow, an older project in the same monorepo). Refine has gone through several major versions with real breaking changes — always cross-check against the **installed** `@refinedev/core` / `@refinedev/antd` versions (`package.json` or `node_modules/@refinedev/core/package.json`) before assuming a snippet applies as-is.

1. **Hook return shape changed across core versions.** Current docs return `{ result, query }` (queries) / `{ mutate, mutation }` (mutations). Older code/tutorials return a flatter `{ data, isLoading }` shape (e.g. via `queryResult`). If TypeScript complains about a property that "should" exist per an example, this is the first thing to check.
2. **React Router package name.** Current docs install `react-router` directly (v7-unified package). Older Refine + React Router v6 setups use `react-router-dom`. Check which one is already a dependency before adding an import.
3. **`ThemedLayout` is deprecated** in favor of `ThemedLayoutV2` (+ `ThemedSiderV2`/`ThemedHeaderV2`/`ThemedTitleV2`). Always use the V2 family in new code; if you find bare `ThemedLayout` in the existing project, that's a signal it predates a migration, not a reason to introduce more of it.
4. **antd v4 → v5 migration debris.** Legacy `@pankod/refine-antd@3.x` targeted antd v4 (LESS theming). `@refinedev/antd@4.x+` targets antd v5 (CSS-in-JS/token theming). Watch for:
   - Old CSS import `@refinedev/antd/dist/styles.min.css` → current is `@refinedev/antd/dist/reset.css`. The old path silently produces no output on v5 — a blank/unstyled app with no error is the symptom.
   - Prop renames: `actionButtons` → `headerButtons`, `pageHeaderProps` → `headerProps` on `List`/`Create`/`Edit`/`Show`.
   - Custom `Menu` swizzles need `theme="dark"` added under antd v5 sider theming.
   - Custom `Header` swizzles should drop any hardcoded `backgroundColor: '#fff'` — it fights `ConfigProvider` theming.
   - Automated codemod exists: `npx @refinedev/codemod antd4-to-antd5` — does **not** touch custom component styling, which still needs manual review after running it.
5. **`useNotificationProvider` requires antd's `<App>` wrapper** (`import { App as AntdApp } from "antd"`, wrapping `<Refine>`). Without it, antd v5's static `message`/`notification` calls lose access to theme context — symptom: notifications appear unstyled or not themed, not a hard crash, which makes this easy to miss.
6. **`useSelect` does not manage controlled state on its own.** Fine inside an antd `<Form.Item>` (which binds `value`/`onChange` automatically). Outside one, you must wire `value`/`onChange` yourself.
7. **`getMany` is optional on a data provider but should usually be implemented.** Omitting it makes Refine fall back to one `getOne` per id — a correctness-preserving but performance-degrading fallback that's easy to not notice until a table with a relation column gets slow.
8. **`mutationMode` defaults to `"pessimistic"`** everywhere (wait for the server before navigating/toasting). If a task asks for "instant" or "optimistic" UI feedback on save/delete, that's a `mutationMode: "optimistic"` or `"undoable"` override on the specific hook call — not a global framework limitation.
9. **Resource `name` vs `identifier`.** Hooks key their cache off `name` by default. If a task needs two differently-configured views of the same backend resource, give the second one a distinct `identifier` — otherwise their query caches collide and one view's refetch can silently stomp the other's data.
10. **Tutorial page URLs on refine.dev have churned.** If you (the assistant) go fetch live docs pages during a task and hit a 404 on a `tutorial/essentials/...` sub-path, fall back to the stable `docs/data/...`, `docs/authentication/...`, `docs/ui-integrations/ant-design/...` reference paths — those are far more stable than the tutorial's own internal links.
